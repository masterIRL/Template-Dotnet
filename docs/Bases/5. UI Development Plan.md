# Project Template-Dotnet: Advanced UI Development Plan (MAUI App)

This plan outlines the UI components, layout, and interactions for each screen of the MAUI application. It considers both Configuration 1 (Standalone, No Authentication) and Configuration 2 (Multi-User with API Backend, Authentication Enabled).

---

## I. Global UI Components & Patterns

Before detailing individual screens, let's define global components and patterns that ensure consistency and a high-quality user experience. These will leverage .NET MAUI's capabilities, including XAML Styling, CSS (where appropriate), and the MVVM pattern with `CommunityToolkit.Mvvm`. Navigation will primarily use .NET MAUI Shell.

1.  **Navigation System (MAUI Shell):**
    * **Flyout Menu (Optional, for Config 2):** Accessible via a hamburger icon in the header. Links to: Home (Products), Order History, Profile, Settings, Logout. In Config 1, this might be simpler, perhaps just Home and Settings.
    * **Bottom Tab Bar (Primary Navigation):**
        * **Products:** Icon (e.g., storefront or grid icon). Default active tab.
        * **Cart:** Icon (e.g., shopping cart icon) with a dynamic badge indicating item count.
        * **Orders:** Icon (e.g., list or receipt icon) for Order History.
        * **Profile/Account (Config 2):** Icon (e.g., user silhouette). In Config 1, this tab might be absent or link to a simpler "Settings/About" page.
    * **Header Bar:**
        * **Title:** Dynamically updated based on the current screen.
        * **Back Button:** Standard platform-specific back arrow for navigating to the previous screen in a stack.
        * **Action Icons (Contextual):** E.g., Search icon on Product List.

2.  **Interactive Elements & Feedback:**
    * **Buttons:**
        * **Primary CTA:** Prominent, solid background (e.g., primary color), clear text. States: Default, Pressed (slight scale down/darken), Disabled (reduced opacity, non-interactive).
        * **Secondary Button:** Outlined or lighter background. States similar to Primary.
        * **Text Button:** For less critical actions (e.g., "View Details," "Forgot Password?"). Color change on press.
        * **Icon Button:** For actions like search, filter, add to cart (on product cards). Clear visual feedback on tap.
    * **Input Fields:**
        * **Layout:** Label above or floating label. Clear placeholder text.
        * **States:** Default, Focused (border highlight, accent color), Error (red border, error message below), Disabled.
        * **Accessory Icons:** E.g., Show/Hide password, clear text.
    * **Cards:** Used for product items, order summaries, etc. Slight shadow for depth, rounded corners. Interactive cards should have a visual cue on press (e.g., subtle lift or overlay).

3.  **Notifications & Alerts (UC-RN-001):**
    * **Toast Notifications:** Non-intrusive, short-lived messages for events like "Item added to cart," "Order status updated." Positioned at the bottom or top of the screen.
    * **In-App Banners/Dialogs:** For critical information, errors, or confirmations (e.g., "Payment Failed," "Confirm order cancellation?").
        * **Success:** Green accent.
        * **Error:** Red accent.
        * **Warning:** Yellow accent.
        * **Info:** Blue accent.

4.  **Loading States:**
    * **Full-Screen Loader:** Centered activity indicator (e.g., `ActivityIndicator` or custom Lottie animation) with an optional "Loading..." message for initial data loads or blocking operations.
    * **Partial/Skeleton Loaders:** Use shimmering placeholder shapes (skeleton screens) for list items or content areas while data is being fetched, enhancing perceived performance.
    * **Button Loaders:** Integrate a small activity indicator within a button when an action triggers a background process.

5.  **Empty States:**
    * Visually appealing layouts for when lists or content areas are empty (e.g., "Your cart is empty," "No products found," "No order history").
    * **Components:** Engaging icon/illustration, a clear message, and an optional Call to Action (e.g., "Start Shopping" button for an empty cart).

6.  **Search Bar Component:**
    * **Layout:** Rounded input field with a search icon. Clear button (`X`) appears when text is entered.
    * **Interaction:** Real-time filtering or search-on-submit. Placeholder text: "Search products..."

7.  **Forms:**
    * Logical grouping of input fields. Clear visual hierarchy.
    * Validation messages displayed inline near the respective field.
    * A primary submit button, disabled until all required fields are valid (or provides clear feedback on why submission failed).

8.  **Localization & Internationalization (CC-LI-001, CC-LI-002):**
    * All static UI text (labels, button text, messages) sourced from resource files for localization.
    * Dates, times, numbers, and currency formatted based on device locale or user preference.

## II. Core Application Screens

### 1. Splash Screen
* **Objective:** Initial branding and loading screen.
* **Layout:** Centered.
* **UI Components:**
    * **App Logo:** Prominently displayed.
    * **App Name/Tagline (Optional):**
    * **Background:** Solid color (e.g., primary brand color) or subtle gradient.
    * **Activity Indicator (Optional):** If initial setup/loading takes time.
* **Behavior:** Transitions automatically to Onboarding or Product List Screen after a short duration or completion of initial tasks.

### 2. Onboarding Screens (Optional, but recommended)
* **Objective:** Introduce users to key app features or benefits. Usually 2-4 screens.
* **Layout:** Full-screen, swipeable carousel.
* **UI Components (per screen):**
    * **Illustration/Image:** Engaging visual representing the feature.
    * **Headline Text:** Concise and impactful.
    * **Body Text:** Brief description.
    * **Page Indicator:** Dots or progress bar showing current step.
    * **"Next" / "Skip" / "Get Started" Buttons:**
* **Behavior:** Navigates to Product List (or Login for Config 2 if authentication is mandatory before Browse).

### 3. Product List Screen (UC-PC-001) (Home Screen)
* **Objective:** Display available products; allow users to browse and select products.
* **Layout:**
    * **Header:** Screen Title ("Products" or App Name), Cart Icon (with badge), Search Icon.
    * **Search Bar:** Positioned below the header, possibly expanding upon tap of search icon.
    * **Product Grid/List:** Scrollable area displaying product cards. User preference for grid/list view can be a setting.
* **UI Components:**
    * **Product Card (Repeated for each product):**
        * **Product Image (Placeholder):** `Image` control.
        * **Product Name:** `Label` (bold, prominent).
        * **Short Description (Optional):** `Label` (smaller text, truncated).
        * **Price:** `Label` (formatted currency).
        * **"Add to Cart" Button/Icon:** Quick add functionality (specifies quantity '1' by default or opens a small quantity selector).
        * **Tap Area:** Entire card tappable to navigate to Product Detail Screen.
    * **Filtering/Sorting Options (Optional):** Accessible via an icon (e.g., filter icon) opening a bottom sheet or a separate view.
    * **Loading Indicator/Skeleton Screen:** While products are loading.
    * **Empty State:** If no products are available or match search/filter criteria ("No products found. Try a different search?").
* **Interactions:**
    * Tapping a product card navigates to `Product Detail Screen`.
    * Tapping "Add to Cart" adds the item and updates the cart icon badge.
    * Search bar filters the product list in real-time or on submit.

### 4. Product Detail Screen
* **Objective:** Provide comprehensive information about a single product and allow adding to order.
* **Layout:**
    * **Header:** Product Name (dynamic), Back Button, Cart Icon.
    * **Content Area (Scrollable):**
        * **Product Image Carousel:** Multiple images if available, swipeable. `CarouselView`.
        * **Product Name:** `Label` (large, bold).
        * **Full Description:** `Label` (detailed text).
        * **Price:** `Label` (prominent, formatted currency).
        * **Quantity Selector:**
            * `Label`: "Quantity"
            * Stepper control (`Stepper`) or Minus Button, Quantity `Entry` (read-only or editable), Plus Button.
        * **"Add to Order" Button:** Primary CTA. Text could be "Add to Cart" or "Add to Order."
* **UI Components:** As listed above.
* **Interactions:**
    * Quantity selector updates the desired quantity.
    * "Add to Order" button adds the specified quantity of the product to the current order, provides feedback (e.g., toast "Added to cart!"), and updates cart icon badge. Button may become "Update Quantity in Cart" if already added.

### 5. Shopping Cart Screen (UC-OM-002, UC-OM-003, UC-OM-004)
* **Objective:** Allow users to view, modify, and manage items in their current order before checkout.
* **Layout:**
    * **Header:** "My Cart" or "Current Order," Back Button (if navigated from another screen, else part of tab view).
    * **Order Item List (Scrollable):**
    * **Order Summary Section (Fixed or at bottom):**
* **UI Components:**
    * **Order Item Card (Repeated):**
        * **Product Image (Small):** `Image`.
        * **Product Name:** `Label`.
        * **Unit Price:** `Label`.
        * **Quantity Selector:** Minus Button, Quantity `Label` or `Entry`, Plus Button (UC-OM-003). Modifying quantity updates subtotal and total. If quantity becomes zero, a confirmation for removal might appear, or item is removed (UC-OM-004).
        * **Item Subtotal:** `Label` (Price * Quantity).
        * **Remove Item Button:** `Button` or `ImageButton` (e.g., trash icon) (UC-OM-004).
    * **Order Summary:**
        * **Subtotal:** `Label` (sum of all item subtotals).
        * **Shipping (Placeholder):** `Label` ("Calculated at next step").
        * **Taxes (Placeholder):** `Label` ("Calculated at next step").
        * **Total Order Amount:** `Label` (bold, prominent).
    * **"Proceed to Checkout" Button:** Primary CTA. Disabled if cart is empty.
    * **Empty State:** "Your cart is empty. Let's find something for you!" with a "Shop Now" button linking to Product List.
* **Interactions:**
    * Quantity modification updates item subtotal and order total instantly.
    * Removing item updates the list and totals.
    * "Proceed to Checkout" navigates to the first step of the Checkout Flow.

### 6. Checkout Flow
This is a multi-step process. Navigation between steps should be clear (e.g., "Next: Payment," "Back to Shipping"). A progress indicator (e.g., Stepper UI) at the top can be beneficial.

#### 6.a. Shipping Address Screen (UC-OM-005)
* **Objective:** Allow users to add or select a shipping address.
* **Layout:**
    * **Header:** "Shipping Address," Back Button.
    * **Option to Select Existing Address (Config 2, if user has saved addresses):** `ListView` or `CollectionView` of saved address cards. Each card shows address summary and a "Select" button or is tappable.
    * **"Add New Address" Button/Form:**
* **UI Components (for Add New Address Form):**
    * `Entry` for Street (e.g., "Street Address Line 1")
    * `Entry` for Apt, Suite, etc. (Optional, "Street Address Line 2")
    * `Entry` for City
    * `Picker` or `Entry` for State/Province
    * `Entry` for Postal Code
    * `Picker` for Country (pre-filled based on locale if possible)
    * `Switch` or `CheckBox` for "Save this address for future use" (Config 2).
    * **"Continue to Payment" / "Save Address" Button:** Primary CTA.
* **Interactions:**
    * Form validation for all fields.
    * Selecting an existing address auto-fills the details.
    * Proceeds to Payment Method Screen. In Config 1, the address is session-based.

#### 6.b. Payment Method Screen (UC-OM-006 - Simulated)
* **Objective:** Allow users to add or select mock payment details.
* **Layout:**
    * **Header:** "Payment Method," Back Button.
    * **Option to Select Existing Mock Payment (Config 2, if applicable):** List of saved mock payments (e.g., "FakeCard ending in 1234").
    * **"Add New Payment Method" Section:**
* **UI Components (for Add New Mock Payment):**
    * `Label`: "Select a Mock Payment Type"
    * `Picker` or `RadioButtons`: Options like "Simulated Visa ending 1234," "Simulated MasterCard ending 5678," "Simulated PayPal."
    * (No actual card input fields for simplicity as per spec).
    * `Switch` or `CheckBox` for "Save this payment method" (Config 2).
    * **"Continue to Review" / "Save Payment" Button:** Primary CTA.
* **Interactions:**
    * Proceeds to Order Summary & Confirmation Screen.

#### 6.c. Order Summary & Validation Screen (Leads to UC-OM-007)
* **Objective:** Allow users to review all order details before final submission.
* **Layout:**
    * **Header:** "Review Order," Back Button.
    * **Sections (Read-only summaries):**
        * **Shipping Address:** Display selected address with an "Edit" link/button.
        * **Payment Method:** Display selected mock payment with an "Edit" link/button.
        * **Order Items:** Collapsible list of items (Product Name, Image, Quantity, Price, Item Subtotal). Similar to cart but non-editable quantities here (edit by going back to cart).
    * **Detailed Order Totals:**
        * **Subtotal:** `Label`.
        * **Shipping Cost (Simulated/Fixed):** `Label`.
        * **Taxes (Simulated/Fixed):** `Label`.
        * **Grand Total:** `Label` (bold, large).
    * **"Place Order" / "Validate Order" Button:** Primary CTA (UC-OM-007).
* **Interactions:**
    * "Edit" links navigate back to respective screens.
    * "Place Order" triggers order validation. UI shows a loading indicator.
        * On success, navigates to `Order Success Screen`. Status changes to `Pending_Payment` or `In_Progress`. `OrderValidatedEvent` is raised.
        * On failure (e.g., validation error from backend), displays an error message.

### 7. Order Success/Failure Screen
* **Objective:** Inform the user about the outcome of their order placement.
* **Layout:** Centered, full-screen.
* **UI Components (Success):**
    * **Success Icon:** Large checkmark or celebratory illustration.
    * **Headline:** "Order Placed Successfully!"
    * **Message:** "Your order # [Order_ID] has been confirmed. You will receive updates on its status." (Order ID displayed).
    * **"View Order Details" Button:** Navigates to `Order Details Screen` for this new order.
    * **"Continue Shopping" Button:** Navigates to `Product List Screen`.
* **UI Components (Failure - e.g., if immediate payment simulation fails as per UC-FS-001):**
    * **Failure Icon:** Large 'X' or warning illustration.
    * **Headline:** "Order Placement Failed" or "Payment Failed."
    * **Message:** "Unfortunately, we couldn't process your order. Reason: [Error_Message]." (e.g., "Simulated payment declined").
    * **"Retry Payment" Button (If applicable):** Navigates back to Payment Screen or Order Summary.
    * **"View Cart" Button:** To review/modify cart.
    * **"Contact Support" (Optional):**
* **Interactions:** Buttons navigate as described.

### 8. Order History Screen (UC-OM-008)
* **Objective:** Display a list of user's past and current orders.
* **Layout:**
    * **Header:** "My Orders," Back Button (if applicable).
    * **Order List (Scrollable):** `CollectionView` or `ListView` of order summary cards.
* **UI Components:**
    * **Order Summary Card (Repeated):**
        * **Order ID:** `Label` (e.g., "Order #12345").
        * **Order Date:** `Label`.
        * **Total Amount:** `Label`.
        * **Order Status:** `Label` with a distinct visual style per status (e.g., color-coded badge: `Draft` (Grey), `Pending_Payment` (Orange), `Payment_Failed` (Red), `In_Progress` (Blue), `Shipped` (Purple), `Delivered` (Green), `Cancelled` (Dark Grey)).
        * **"View Details" Button or Tappable Card:**
    * **Filtering/Sorting (Optional):** By status, date range.
    * **Loading Indicator/Skeleton Screen:**
    * **Empty State:** "You haven't placed any orders yet." with a "Shop Now" button.
* **Interactions:**
    * Tapping an order card or "View Details" navigates to `Order Details Screen`.
    * In Config 1 (no auth), this list might show session/device-local orders.

### 9. Order Details Screen (UC-OM-008)
* **Objective:** Display detailed information for a specific past or current order.
* **Layout:**
    * **Header:** "Order Details" or "Order #[Order_ID]," Back Button.
    * **Content Area (Scrollable):**
* **UI Components:**
    * **Order Information Section:**
        * **Order ID:** `Label`.
        * **Order Date:** `Label`.
        * **Current Order Status:** `Label` (prominent, styled by status).
        * **Status History/Timeline (Optional, Advanced):** Visual representation of status changes.
    * **Ordered Items Section:**
        * List of `ProductItemView` (similar to cart item but read-only: Image, Name, Quantity, Price, Item Subtotal).
    * **Shipping Information Section:**
        * **Shipping Address:** Displayed as text.
    * **Payment Information Section:**
        * **Payment Method (Mock):** Displayed as text (e.g., "Paid with FakeCard ending 1234").
        * **Invoice (Simulated):** "Invoice: Generated (Simulated)" (UC-FS-001).
    * **Order Totals Section:** Subtotal, Shipping, Taxes, Grand Total.
    * **Action Buttons (Contextual):**
        * "Cancel Order" Button (If status allows, e.g., `Pending_Payment` or `In_Progress` before shipping). Requires confirmation dialog.
        * "Track Shipment" Button (If shipped, links to a mock tracking page or displays mock info).
        * "Reorder" Button (Adds all items from this order to the current cart).
* **Interactions:** Contextual buttons perform their respective actions with appropriate confirmations and feedback. Real-time updates to status may be reflected here if the user is viewing the screen.

## III. Authentication Module Screens (Primarily for Configuration 2)

These screens are typically presented modally or as a separate navigation stack before accessing the main app features in Configuration 2 if authentication is required upfront.

### 10. Login Screen (CC-AA-002.1, CC-AA-002.2)
* **Objective:** Allow existing users to log in.
* **Layout:** Centered form, app logo above.
* **UI Components:**
    * **App Logo/Title:**
    * `Entry` for Email/Username (with appropriate keyboard type).
    * `Entry` for Password (masked, with show/hide password icon).
    * **"Login" Button:** Primary CTA.
    * **"Forgot Password?" Link/Button:** Navigates to `Forgot Password Screen`.
    * **Social Login Section (CC-AA-002.1):**
        * "Or log in with" `Label`.
        * **"Login with Google" Button:** Branded Google button.
    * **"Don't have an account? Sign Up" Link/Button:** Navigates to `Registration Screen`.
* **Interactions:**
    * Form validation.
    * "Login" button attempts authentication, shows loading indicator. On success, navigates to main app (e.g., Product List). On failure, shows error message.
    * Social login initiates OAuth flow.

### 11. Registration Screen (CC-AA-002.2)
* **Objective:** Allow new users to create an account.
* **Layout:** Centered form, app logo above.
* **UI Components:**
    * **App Logo/Title:**
    * `Entry` for Username (Optional, if email is not username).
    * `Entry` for Email.
    * `Entry` for Password (masked, with show/hide icon, password strength indicator).
    * `Entry` for Confirm Password (masked).
    * `CheckBox` for "I agree to Terms & Conditions and Privacy Policy" (with links).
    * **"Sign Up" / "Create Account" Button:** Primary CTA, disabled until form is valid and T&Cs accepted.
    * **"Already have an account? Login" Link/Button:** Navigates to `Login Screen`.
* **Interactions:**
    * Form validation (email format, password match, password strength).
    * "Sign Up" attempts registration. On success, may navigate to Login Screen or directly into app (optionally after email verification step). On failure (e.g., email already exists), shows error.

### 12. Forgot Password Screen (CC-AA-002.2)
* **Objective:** Allow users to initiate password reset process.
* **Layout:** Centered form.
* **UI Components:**
    * **Instruction Text:** "Enter your email address to receive a password reset link/code."
    * `Entry` for Email.
    * **"Send Reset Link" / "Get Code" Button:** Primary CTA.
    * **"Back to Login" Link/Button:**
* **Interactions:**
    * Validates email. On submit, calls backend API. Shows confirmation message ("If an account exists for [email], you will receive reset instructions."). Navigates to a screen confirming email sent or directly back to login.

### 13. Reset Password Screen (CC-AA-002.2)
* **Objective:** Allow users to set a new password using a token/code.
* **Layout:** Centered form.
* **UI Components (if using code):**
    * **Instruction Text:** "Enter the code sent to your email and your new password."
    * `Entry` for Reset Code/OTP.
    * `Entry` for New Password (masked, strength indicator).
    * `Entry` for Confirm New Password (masked).
    * **"Reset Password" Button:** Primary CTA.
* **Interactions:**
    * Validates code and new passwords. On success, shows "Password reset successfully" message and navigates to Login Screen. On failure, shows error.

## V. Vibe, Theme, and Color Palette

* **Vibe/Theme:**
    * **Modern & Clean:** Minimalist aesthetic, ample white space, clear typography. Focus on usability and clarity, reflecting the "Clean Architecture" principles.
    * **Professional & Trustworthy:** The design should instill confidence, suitable for a boilerplate that will be the foundation of other applications.
    * **Tech-Forward yet Approachable:** While the users of the template are developers, the sample application UI should be user-friendly for any end-user.
    * **Neutral & Adaptable:** As a template, the core design should be easily customizable or themeable.

* **Typography:**
    * **Primary Font:** A clean, sans-serif font family standard on mobile platforms or a well-chosen embeddable font (e.g., Inter, Roboto, Open Sans).
    * Clear hierarchy using font weights (Light, Regular, Medium, SemiBold, Bold) and sizes.

* **Color Palette:**
    * **Primary:** A sophisticated, professional blue.
        * Example: `#005A9C` (Deep Cerulean) or `#2563EB` (Modern Blue)
    * **Secondary/Accent (for CTAs, highlights):** A vibrant, contrasting color.
        * Example: `#10B981` (Emerald Green) or `#F59E0B` (Amber)
    * **Neutrals:**
        * **Backgrounds:** `#FFFFFF` (White) and `#F3F4F6` (Light Gray - for subtle divisions or card backgrounds).
        * **Text:** `#1F2937` (Dark Gray - for primary text), `#4B5563` (Medium Gray - for secondary text), `#9CA3AF` (Light Gray - for placeholders/hints).
        * **Borders/Dividers:** `#D1D5DB` (Gray) or `#E5E7EB` (Lighter Gray).
    * **Status Colors:**
        * **Success:** `#10B981` (Green) or a similar shade.
        * **Error/Failure:** `#EF4444` (Red).
        * **Warning/Pending:** `#F59E0B` (Amber/Yellow).
        * **Informational:** `#3B82F6` (Blue).
    * **Dark Mode (Consideration for advanced theming):** A corresponding dark theme palette would invert lightness values, ensuring readability and maintaining brand consistency.

## VI. UI Flow (Brief)

**Configuration 1 (Standalone, No Auth):**

1.  Splash Screen -> (Optional Onboarding) -> Product List Screen.
2.  **Product Browse & Cart:** Product List -> Product Detail -> Add to Cart (updates Cart Icon) -> Cart Screen.
3.  **Checkout:** Cart Screen -> Shipping Address -> Payment Method (Mock) -> Order Summary & Validation -> Place Order.
4.  **Order Outcome:** Order Success/Failure Screen.
5.  **Post-Order:** View Order Details (from Success screen or History) / Continue Shopping.
6.  **Order History:** Accessible from Tab Bar/Menu -> Order History Screen -> Order Details Screen.
7.  **Settings:** Accessible from Tab Bar/Menu -> Settings Screen.

**Configuration 2 (Authenticated):**

1.  Splash Screen -> (Optional Onboarding) -> **Login Screen** (if not authenticated).
    * Login -> Product List Screen.
    * Login -> Registration Screen -> Login.
    * Login -> Forgot Password -> Reset Password -> Login.
2.  **Product Browse & Cart:** (Same as Config 1, but actions are associated with authenticated user).
3.  **Checkout:** (Same as Config 1, but addresses/payments can be saved/selected for the user).
4.  **Order Outcome:** (Same as Config 1).
5.  **Post-Order:** (Same as Config 1).
6.  **Order History:** (Same as Config 1, shows user-specific orders).
7.  **Profile & Settings:**
    * Profile Screen (from Tab Bar/Menu) -> Manage Account aspects, Logout.
    * Settings Screen (from Tab Bar/Menu) -> Configure app settings.
